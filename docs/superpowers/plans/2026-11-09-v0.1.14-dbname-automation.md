# v0.1.14 收尾：数据库名自动化（源/目标分离）

> **For agentic workers:** 内联执行（executing-plans）。步骤用 `- [ ]` 跟踪。

**Goal:** 让恢复尽量少人工介入：源库名从备份包元数据读取，目标库名自动发现并持久化；只有目标库名无法可靠确定时才要求人工填写。

**Architecture:** 新增 `lib/package-meta.js`（从备份包读 `MANIFEST.json` 的 `source.dbName`）与 `lib/dbname-autodiscover.js`（目标机按 dbfilter → db_name → PG 列表推断）。二者严格分离：`sourceDbName` 只用于展示与冲突提示，`targetDbName` 才决定覆盖哪个库。

**Tech Stack:** Node ESM、`node:test`、系统 `tar`、现有 `crypto.js`/`execRemote`。

**Spec:** 本会话用户最终建议（2026-11-09）六点范围。

## Global Constraints

- **源库名 ≠ 目标库名**：源库名（`tg-odoo`）绝不能被当作目标库名使用。
- `db_name` / `dbfilter` / `pgSuperUser` 是不同概念：`pgsql` 是 PG 超级用户，不是数据库名。
- 自动发现不可靠时 **fail-closed**：不猜，要求人工填写。
- 现有 `server.dbName` 手工配置保留，且优先级最高（显式覆盖）。
- 不改变 R10 加解密、Credentials、SSH 指纹、confirmToken、状态机、备份格式。
- 版本仍为 `0.1.14`（作为最终发布内容），构建后重新记录 SHA256。

### Task 1: `lib/package-meta.js` — 从备份包读源库名

**Interfaces:**
- Produces: `export async function readPackageMeta(packagePath, deps = {})` → `{ ok, sourceDbName, source, manifest?, reason? }`

判定：
1. `detectFormat(packagePath)`；
2. `dsh-odoo` → 先解密到临时文件（复用 `decryptFile`，需要 passphrase），`plain` → 直接用；`empty` → 拒绝；其他格式 → 拒绝（不猜）；
3. 用系统 `tar -xOf <file> ./MANIFEST.json` 读取（只读、不落盘完整包）；
4. 解析 `manifest.source.dbName`，必须是非空字符串；
5. 返回 `{ ok:true, sourceDbName, source }`；任何一步失败返回 `{ ok:false, reason }`，**绝不抛到 UI**。

  - 明文包：直接读 → `tg-odoo`
  - 包内无 MANIFEST / 无 source.dbName → `ok:false`
  - `age`/`openssl` 格式 → `ok:false`（不猜）
  - 空包 → `ok:false`

### Task 2: `lib/dbname-autodiscover.js` — 目标机自动发现

**Interfaces:**
- Produces: `export function resolveDiscoveredDbName({ confDbFilter, confDbName, pgDatabases, configuredDbName })` → `{ ok, dbName, source, confidence, candidates?, reason? }`

优先级与语义（严格区分概念）：
1. `configuredDbName` 非空 → `{ ok, dbName, source:'config', confidence:'explicit' }`（人工配置最高优先）
2. `confDbFilter` 有效（非 `.*`、非空）→ `{ ok, dbName, source:'dbfilter', confidence:'high' }`
3. `confDbName` 有效 → `{ ok, dbName, source:'db_name', confidence:'high' }`
4. PG 列表里排除系统库（`postgres/template0/template1/pgsql`）后**恰好一个** → `{ ok, dbName, source:'pg-list', confidence:'medium' }`
5. 多于一个候选 → `{ ok:false, reason:'ambiguous', candidates }`（**不猜**，要求人工）
6. 无候选 → `{ ok:false, reason:'none' }`

`pgSuperUser`（如 `pgsql`）绝不进入候选（系统库/角色排除名单）。

- [ ] Step 2 RED → Step 3 实现 → Step 4 GREEN

### Task 3: `/discover` 自动持久化 + `/precheck` 源/目标展示

**`index.js`：**
- `/discover`：调用 `service.discover()` 后，若某服务器配置里 `dbName` 为空且发现结果给出可自动确定的库名（confidence high/medium），用 `settings.update(entryId, { servers: [...] })` 写回，并在 response 加 `autoDetectedDbName`。**只在自动识别成功时写**；`ambiguous`/`none` 不写、不覆盖。
- `/precheck`：读备份包元数据（`readPackageMeta`，需要 Credentials 口令解密）得到 `sourceDbName`；调用 `service.discover(server)` 得到 `targetDbName`；返回
  ```
  { ok:true, confirmToken, expiresInSeconds:300,
    sourceDbName, targetDbName,
    conflict: sourceDbName === targetDbName ? 'same-name' : null,
    warning: '...' }
  ```
  token 仍绑定 `server + packagePath + neutralize`（**不把库名塞进 token 绑定**，避免加密包元数据变化导致 token 失配），但把库名作为展示信息返回。
- 新增 `GET/POST /restore-meta`：给 UI 只读展示用（同样走 `readPackageMeta`）。

**`client.js`：**
- 恢复页在点「执行恢复」**之前**先调 `/restore-meta`，展示「来源库：tg-odoo / 目标库：toogel / 无冲突」或冲突提示；
- precheck 返回后把 `sourceDbName`/`targetDbName`/`conflict` 显示在状态行；
- 服务器表单保留 `dbName` 输入框（人工兜底），说明「留空=自动发现」。

- [ ] Step 1 写失败测试 `test/restore-precheck-dbname.test.js`：
  - `/precheck` 返回 `sourceDbName` 与 `targetDbName` 两个独立字段
  - `sourceDbName` 来自包元数据、`targetDbName` 来自发现结果（二者不同时不互相污染）
  - 同名时 `conflict='same-name'`
  - token 绑定的 `packagePath` 不变（引号规范化仍生效）
  - `/discover` 自动识别成功写 `settings.update`；`ambiguous` 不写
  - `pgsql` 不会成为 targetDbName
